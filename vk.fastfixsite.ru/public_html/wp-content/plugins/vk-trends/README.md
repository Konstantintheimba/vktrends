# VK Trends 0.17.0

Приватный WordPress-дашборд для наблюдения за постами и видео сообществ VK: сбор счётчиков, динамика просмотров, сводка по сообществам и ручная подборка товаров. Не зависит от темы. Требования: WordPress 6.6+, PHP 8.0+, MySQL/MariaDB с InnoDB, OpenSSL, исходящий HTTPS к `api.vk.com`.

## Автопостинг 0.17.0

Появился отдельный раздел **Автопостинг**. Он не смешивает наблюдаемые источники с сообществами, которыми вы управляете: кнопка «Обновить мои группы» получает через `groups.get(filter=editor)` только группы, где владелец токена является администратором или редактором. Групп может быть несколько, ненужные отключаются локально.

В редакторе можно выбрать несколько групп, написать один текст, приложить файлы с сервера сайта, при необходимости добавить уже загруженные в VK вложения (`photo-123_456`, `video-123_456` и другие поддерживаемые `wall.post` ID), включить подпись автора/закрытые комментарии и задать время. Суммарный предел — 10 вложений, среди которых не больше одной внешней ссылки. Если время не задано, кнопка сразу вызывает публикацию; будущая дата ставит запись в очередь. Ручную проверку черновика при необходимости можно отдельно включить в настройках. Расписание хранится в UTC, а форма принимает локальное время устройства. WP-Cron проверяет очередь раз в минуту отдельным событием `vkt_publish`; пауза сбора трендов автопостинг не останавливает.

Каждая группа получает отдельное задание и стабильный `guid`: повтор временной ошибки не создаёт дубликат записи. Интерфейс показывает ссылку на опубликованный пост и отдельный результат каждого адресата. Отменяется только ещё не отправленная часть; опубликованные посты из VK автоматически не удаляются.

По [актуальной документации `wall.post`](https://dev.vk.com/ru/method/wall.post) основной описанный способ публикации — пользовательский токен Standalone-приложения через Implicit Flow. Право `wall` для такого приложения VK выдаёт в исключительных случаях. Живая проверка 14.09.2026 уточнила недокументированное поведение: ключ сообщества с правом `wall` успешно публикует от имени этой же группы, но получает ошибку 214 при попытке писать в чужую. Поэтому отдельный ключ сообщества используется только для своего `VKT_COMMUNITY_ID`, а пользовательский токен с `groups` нужен для работы сразу с несколькими управляемыми группами. Методы записи намеренно не добавлены в «Тест API» и вызываются только серверным закрытым модулем.

### Файлы с сервера вместо ручного поиска ID вложения

Версия 0.17.0 убирает ручной ввод `photo…` ID. В конструкторе записи файл выбирается из медиатеки WordPress, загружается прямо с компьютера (`POST /wp-json/vk-trends/v1/media-upload`, право `upload_files`) либо создаётся генерацией. Плагин хранит только ID вложения WordPress, а ID вложения VK получает сам при отправке — отдельно для каждого сообщества-адресата, потому что `photos.saveWallPhoto` привязывает фотографию к конкретной группе. Полученный ID кэшируется в задании, поэтому повтор после сетевой ошибки не загружает тот же файл дважды. Принимаются изображения и MP4-видео до 100 МБ, до 10 файлов на запись.

Нативная загрузка идёт документированным путём `photos.getWallUploadServer` → `multipart/form-data` → `photos.saveWallPhoto` и **требует пользовательского токена**.

Ключ сообщества медиа прикладывать не может — это проверено живыми запросами 14.09.2026 на ключе с правами `photos, docs, messages, wall, manage, stories, market`:

| попытка | ответ VK |
|---|---|
| `photos.getWallUploadServer`, `photos.getUploadServer`, `photos.getMarketUploadServer`, `docs.getUploadServer` | ошибка **27** `method is unavailable with group auth` |
| `docs.getWallUploadServer` | ошибка **15** `User can't upload docs to this group` |
| `video.save` | ошибка **5** `invalid token type` |
| `photos.getMessagesUploadServer` → `photos.saveMessagesPhoto` | **проходит**, фото получает `owner_id = -GROUP_ID`, но `wall.post` молча публикует запись **без вложения** |
| публичная ссылка на файл в `attachments` | ошибка **100** |

Работающего обходного пути нет, поэтому с 0.17.0 плагин не притворяется: если файлы приложены, а пользовательского токена нет, запись **отклоняется сразу при создании** с объяснением, а не уходит в очередь и падает кодом VK. В конструкторе блок файлов в этом режиме заменяется объяснением. Текстовые записи ключом сообщества публикуются как раньше.

### Подключение пользовательского токена через VK ID

Так как медиа требует пользовательского токена, версия 0.17.0 получает его сама. В настройках указывается **ID приложения** из консоли `dev.vk.ru` (это не секрет — он виден в адресе страницы согласия), кнопка «Подключить VK ID» проводит OAuth 2.1 с PKCE и сохраняет комплект `access_token` + `refresh_token` + `device_id` + `client_id`, который `VKT_API::maybe_refresh()` затем обновляет сам за 5 минут до истечения.

Что важно знать, по результатам живых проверок 14.09.2026:

- Устаревший `oauth.vk.com/authorize` (Implicit Flow) отдаёт токен без `refresh_token`, то есть примерно на сутки — для автопостинга не подходит.
- Право **`offline` больше не существует**: `oauth.vk.com/authorize` отвечает `invalid scope`. То же для `email` и `phone`. Плагин запрашивает ровно `wall photos groups video`.
- Выключенному приложению VK отвечает `application is disabled` на любой scope. Приложение нужно включить в консоли.
- `redirect_uri` плагина постоянный: `https://ДОМЕН/wp-admin/admin-post.php?action=vkt_vkid`. Его надо внести в доверенные адреса приложения, иначе VK ID вернёт ошибку.
- Константа `VKT_ACCESS_TOKEN` в `wp-config.php` всегда трактуется как сервисный ключ и имеет приоритет над настройками. Пока она задана, пользовательский токен сохранить нельзя — плагин отказывает **до** перехода в VK и говорит об этом в настройках.

**Главное ограничение, выясненное 15.09.2026:** токен, полученный через Implicit Flow в браузере, **привязан к IP** и на сервере не работает — VK отвечает `код 5: User authorization failed: access_token was given to another ip address`. Раньше от привязки спасало право `offline`, но оно отменено: `oauth.vk.com/authorize` отвечает `invalid scope` и на имя `offline`, и на числовые маски (`65536`, `335892`). Поэтому ручная вставка токена годится только для проверки доступности методов, но не для автопостинга с сервера.

Рабочий способ один: **обмен кода на токен должен выполнять сам сервер** — тогда VK выдаёт токен на IP сервера. Это и делает модуль VK ID. Приложение для него создаётся **не в консоли dev.vk.ru, а в кабинете VK ID** (id.vk.ru/about/business): там задаются «Базовый домен» и «Redirect URI», которых у приложений типа VK Mini App нет.

**Ограничение приложений VK Mini App:** доверенный `redirect_uri` должен быть заранее прописан в приложении, а у приложений типа **VK Mini App такого раздела в консоли нет** — в нём только адреса запуска в iframe и публикация в Одноклассниках. Любой свой адрес такое приложение отклоняет: `oauth.vk.com/authorize` отвечает `redirect_uri is incorrect, check application redirect uri in the settings page`, а `id.vk.ru/authorize` — «Ошибка загрузки». Работает только `https://oauth.vk.com/blank.html`, то есть Implicit Flow с ручным переносом токена. Кнопка «Подключить VK ID» рассчитана на приложение, где доверенный адрес задать можно.

Для ручного пути поле «Access token» принимает **целиком адрес из строки браузера** вида `https://oauth.vk.com/blank.html#access_token=…&expires_in=86400&user_id=…`: плагин сам вырезает токен, подставляет срок жизни и выставляет тип «пользовательский». Кнопка «Открыть страницу VK» рядом собирает адрес согласия из сохранённого ID приложения.

Адрес возврата настраивается, а по умолчанию равен корню сайта — без строки запроса, потому что какие формы адреса принимает VK ID, решает консоль VK, а не плагин. Возврат ловится на **любой** странице сайта: плагин опознаёт его по собственному `state` из временной записи, а не по адресу, поэтому доверенный адрес можно менять, не трогая код. Чужой домен в качестве адреса возврата отклоняется.

ID приложения сохраняется независимо от того, задана ли константа `VKT_ACCESS_TOKEN`: пока она на месте, кнопка называется «Сохранить ID приложения» и не уводит в VK впустую, а после её удаления та же кнопка запускает подключение.

Защищённый ключ приложения по умолчанию не нужен — PKCE заменяет аутентификацию клиента. Если VK ID сочтёт приложение серверным и потребует его, добавьте `define( 'VKT_VKID_CLIENT_SECRET', '…' );` в `wp-config.php`: тогда плагин приложит ключ к обмену кода. В интерфейс и REST значение не возвращается, отдаётся только признак наличия.

PKCE-верификатор хранится во временной записи на 15 минут, привязан к начавшему подключение администратору и в адресную строку не попадает; `state` проверяется на возврате. Точка возврата `admin_post_vkt_vkid` доступна только пользователю с `manage_options`, анонимного варианта у неё нет.

Проверено на живом пользовательском токене 14.09.2026:

- `photos.getWallUploadServer` для управляемой группы **работает** — возвращает `album_id: -14` и адрес загрузки с `wallphoto=1`. Загрузка фото пользовательским токеном открыта.
- `video.save` отвечает ошибкой **7** `owner has not right for this action, can't add video`, если в сообществе выключен раздел «Видеозаписи». Включается в «Управление → Настройки → Разделы».
- `groups.getTokenPermissions` пользовательскому токену недоступен (ошибка 5) — это нормально, метод только для ключей сообщества.
- `groups.get` возвращает сообщества, где владелец токена **состоит участником**. Собственное сообщество, созданное администратором без вступления в него (`is_member: 0`), в списке не появится, хотя `groups.getById` показывает `is_admin: 1` и `can_post: 1`. Поэтому адресат из `VKT_COMMUNITY_ID` добавляется в список отдельно и не зависит от `groups.get`.

Запись с файлами публикуется **тем же пользовательским токеном**, который загрузил фотографию: смешивать в одной записи две учётные записи VK не обязан принимать. Текст без вложений в собственное сообщество по-прежнему уходит ключом сообщества — этот путь проверен живой публикацией.

### Генерация текста, изображений и видео

Ключ читается из `VKT_XAI_API_KEY` в `wp-config.php`, остаётся на сервере и не попадает ни в REST-ответы, ни в журнал — наружу уходит только признак «ключ настроен» и названия моделей. Модели: `grok-4.6` для текста, `grok-imagine-image-2.0` для изображений, `grok-imagine-video-1.5` для видео (6 секунд). Соотношение сторон выбирается из списка, который принимает xAI.

Генерация изображений и видео доступна там же, где и файлы, то есть при сохранённом пользовательском токене. Текст возвращается в поле записи как черновик — уже набранный текст передаётся модели как основа. Изображение и видео сохраняются в медиатеку WordPress и сразу прикрепляются к записи, то есть проходят тот же путь, что и любой загруженный файл. Видео у xAI готовится асинхронно: плагин запускает задачу и опрашивает её статус, готовый ролик привязывается к `request_id` на неделю, чтобы повторный опрос не оплачивал генерацию заново. Ни текст, ни медиа не публикуются автоматически — запись уходит в VK только по кнопке.

Ключ из меню сообщества **«Управление → Работа с API → Ключи доступа»** хранится отдельно от общего токена. Плагин проверяет его через `groups.getTokenPermissions`, добавляет принадлежащую ему группу в список адресатов и жёстко запрещает передавать этому ключу другой `owner_id`. Сам токен в журнал и REST не попадает.

### Тестовое сообщество и Callback API

Отдельные константы `VKT_COMMUNITY_ID`, `VKT_COMMUNITY_ACCESS_TOKEN`, `VKT_CALLBACK_CONFIRMATION` и `VKT_CALLBACK_SECRET` читаются из `wp-config.php`. Ключ сообщества не заменяет сервисный ключ сбора, но может публиковать на стене собственного `VKT_COMMUNITY_ID`. Интерфейс получает только ID сообщества, признак настройки и адрес Callback API — сами секреты через REST не возвращаются.

Версия 0.17.0 принимает Callback API по адресу `https://ДОМЕН/wp-admin/admin-post.php?action=vkt_callback`. Запрос проверяется одновременно по `group_id` и `secret`; на событие `confirmation` возвращается строка подтверждения, на остальные корректные события — `ok`. Сырое содержимое события не сохраняется, в журнал попадает только его тип. В настройках есть кнопка серверной проверки ключа, группы и выданных прав. Если хостинг показывает внешним POST-запросам JavaScript-проверку вместо ответа WordPress, Callback URL нужно исключить из антибот-защиты хостинга.

### Необязательная проверка и будущие агенты

Версия 0.17.0 публикует ручную запись сразу по нажатию и содержит необязательный шлюз проверки для будущего агентного контура:

1. агент текста и агент изображения готовят данные;
2. фильтр `vkt_publisher_prepare_draft` передаёт их в общую валидацию;
3. событие `vkt_publisher_draft_created` позволяет поставить редактору отдельное задание;
4. фильтр `vkt_publisher_editor_approval` может отклонить подтверждение;
5. если настройка ручной проверки включена, владелец проверяет итоговый черновик в интерфейсе и только затем отправляет его в очередь.

Режим проверки задаётся только серверной настройкой, а REST-интерфейс не позволяет выдать ручной записи происхождение `agents`. С 0.17.0 генерация и загрузка медиа подключены, но остаются ручными действиями в конструкторе: автономного контура, который сам придумывает и публикует записи, в плагине нет.

Внешняя ссылка во вложениях должна вести на страницу с превью. Прямой адрес файла (`…/photo.jpg`) VK отклоняет ошибкой 100 `Violated: link_photo_sizing_rule. No photo given`, потому что строит из ссылки карточку и не находит изображения нужного размера. С 0.17.0 плагин проверяет это сам и объясняет причину, не доводя до запроса в VK.

### Видно, какой токен сохранён

Полный токен по-прежнему не возвращается в браузер: дашборд открывается и на главной странице сайта, поэтому XSS на ней увела бы доступ к аккаунту. Но «сохранён ли он и тот ли это токен» проверить нужно, поэтому с 0.17.0 интерфейс показывает **огрызок** вида `vk1.a.vf37d_…6Mqmuf` и длину в символах: начало и конец позволяют сверить с тем, что вставляли, и сразу увидеть обрезку.

Сохранение токена сразу же проверяется: плагин выполняет `users.get` и в ответе пишет либо имя аккаунта, либо код и текст отказа VK. Без этого о проблеме можно было узнать только из «Истории» и «Журнала», а там лежат **записи прошлых попыток** — они не обновляются задним числом и легко читаются как текущее состояние. Поэтому рядом с ошибкой доставки теперь всегда стоит время попытки.

Рядом кнопка **«Проверить токен»**: сервер выполняет `users.get` тем самым сохранённым токеном и показывает ответ VK как есть — имя и ID аккаунта либо код ошибки с текстом. Ошибка 5 при живом на вид токене означает, что он просрочен, отозван или сохранён не полностью.

Ошибка VK в истории публикаций и в журнале теперь содержит **название метода и текст VK**: `VK вернул ошибку 1051 [photos.saveWallPhoto: …]`. Без этого по одному коду нельзя понять, отказал VK на загрузке фотографии или уже на самой записи.

### Несколько ключей одновременно

До 0.17.0 плагин хранил **один** ключ, и подключение нового вытесняло предыдущий: пользовательский токен VK ID выбил сервисный, после чего сбор данных и `groups.get` начали отвечать ошибкой 1051. Теперь ключи лежат в независимых слотах и не заменяют друг друга:

| слот | что делает | константа |
|---|---|---|
| `service` | читает стены: посты, видео, счётчики | `VKT_ACCESS_TOKEN` |
| `user` | загружает фото и видео, отдаёт список своих сообществ, публикует | — |
| `community` | публикует текст на стене своей группы | `VKT_COMMUNITY_ACCESS_TOKEN` |

Метод сам выбирает слот: `VKT_API::slot_for()` отдаёт пользовательский токен методам из списка `USER_ONLY` (`video.get`, `groups.get`, `wall.post`, загрузка фото и видео), остальное читает сервисным ключом, а при его отсутствии — любым доступным. Константа всегда важнее сохранённого в настройках и блокирует правку своего слота. Ключи хранятся одной зашифрованной записью AES-256-GCM; единственный ключ прежнего формата переносится в свой слот автоматически при первом обращении.

ID своего сообщества тоже задаётся в настройках, а не только константой `VKT_COMMUNITY_ID`.

### Ошибки видны и закреплены за ключом

Каждый отказ VK записывается в тот слот, чьим ключом был сделан запрос, и держится в карточке ключа, пока следующий успешный запрос его не снимет. Кнопка «Сохранить и проверить» сразу прогоняет набор проб и показывает дословные ответы VK по каждому методу:

- сервисный ключ — `wall.get`;
- ключ сообщества — `groups.getTokenPermissions`;
- пользовательский токен — `users.get`, `groups.get` (право `groups`), `photos.getWallUploadServer` (право `photos`), `wall.post` (право `wall`).

Проба `wall.post` выполняется заведомо неполным запросом: право видно по коду отказа, а запись не создаётся. Коды 100, 113 и 104 при пробе считаются успехом — они означают «метод доступен, не хватает параметров».

### Права токена VK ID видны в настройках

Токен сохраняется вместе со списком прав, которые вернул сам VK ID, и этот список показан в настройках. Без него отказы нечитаемы: VK выдаёт токен даже тогда, когда часть запрошенных прав не предоставлена, и методы потом отвечают «не хватает scope».

Проверено 15.09.2026 на живом токене VK ID приложения 54755819:

- `photos.getWallUploadServer` → ошибка **15**: `Access denied: no access to call this method. It cannot be called with current scopes.` — у токена нет права `photos`;
- `wall.post` → ошибка **1051**: `Method is not available for this profile type: method is unavailable with current profile type` — у токена нет права `wall`.

По [документации VK](https://id.vk.ru/about/business/go/docs/ru/vkid/latest/vk-id/connection/api-description) доступ к работе с сообществами (`groups`, а с ним `wall`) выдаётся **по заявке в техническую поддержку** `devsupport@corp.vk.com`, а не переключателем в кабинете. До одобрения пользовательский токен умеет только читать.

### Лимиты VK, существенные для публикаций

- Пользовательский токен ограничен **3 API-запросами в секунду**, ключ сообщества — **20 запросами в секунду**. Плагин намеренно строже: между адресатами публикации выдерживается 2 секунды. Один пост в пяти группах — это пять отдельных вызовов `wall.post`.
- VK сообщает о дополнительных количественных ограничениях на частые вызовы одного метода, но точные значения не публикует. При превышении возможны временная блокировка метода, flood control или CAPTCHA. Плагин повторяет только временные ошибки с задержкой; CAPTCHA автоматически не решает. См. [лимиты API-запросов](https://dev.vk.com/ru/api/api-requests) и [официальные коды ошибок](https://github.com/VKCOM/vk-api-schema/blob/master/errors.json).
- С 7 сентября 2026 года [правила платформы](https://dev.vk.com/ru/rules) указывают месячный предел на один аккаунт бизнес-кабинета VK ID: 10 000 API-вызовов для неподтверждённого бизнес-профиля и 100 000 000 для подтверждённого. Это лимит всех API-вызовов, а не только публикаций.
- В одной записи `wall.post` допускается до 10 фото/видео, одна внешняя ссылка, один файл и один опрос; отдельные правила действуют для аудио. Текущий интерфейс использует более простой строгий предел: суммарно до 10 элементов, из них не более одной внешней ссылки, одного файла и одного опроса. Аудио не принимается, пока в плагине нет режима карусели.

## Установка на vk.fastfixsite.ru

1. Загрузите папку `vk-trends` в `wp-content/plugins/`.
2. Активируйте **VK Trends**. Плагин создаст собственные таблицы и страницы «VK Trends» и «Тест API VK». Главная начнёт показывать дашборд для администратора, гостя отправит на вход в WordPress.
3. Откройте главную или пункт **VK Trends** в админке → **Настройки**. Выберите тип токена и вставьте его:
   - **Сервисный ключ** — из настроек приложения VK ID. Сбор работает на `wall.get`, точечных замеров и видеораздела источника у него нет.
   - **Пользовательский токен VK ID** — для `wall.post` это токен Standalone-приложения через Implicit Flow с исключительным правом `wall`; для списка групп нужно `groups`, для замеров роликов — `video`. Один `access_token` уже можно сохранить и использовать, но обновлять его придётся вручную. Если способ получения токена также дал `refresh_token`, `device_id` и `client_id`, укажите весь комплект — тогда плагин сможет обновлять пару через `id.vk.ru/oauth2/auth`, когда до истечения останется меньше 5 минут.

   Защищённый ключ приложения (client secret) токеном не является ни для одного из режимов.
4. В **Тест API** выберите `wall.get`, укажите `{"domain": "team", "count": 100}` и выполните запрос. Ошибка VK отображается с кодом и пояснением.
5. Добавьте сообщество в **Источники** и запустите ручной сбор. Для динамики нужны два обхода с интервалом хотя бы в минуту. Сборщик по умолчанию на паузе.

Страница API имеет отдельный шаблон **VK Trends — Тест API**, дашборд — **VK Trends — Дашборд**. Их можно назначить другим страницам в WordPress. В блоковой теме выбор шаблона зависит от редактора, поэтому страницы создаются с назначенными шаблонами автоматически. Отключение настройки «Показывать дашборд на главной» возвращает обычную главную темы; отдельные страницы и пункт админки остаются.

Секреты не включаются в файлы самого плагина. Токен из настроек хранится в отдельной неавтозагружаемой опции одной записью: JSON-структура (`kind`, `access_token`, `refresh_token`, `expires_at`, `device_id`, `client_id`) целиком зашифрована AES-256-GCM с ключом от WordPress auth salt. После смены salts токен нужно сохранить заново. Старый формат опции (просто зашифрованный сервисный ключ, без структуры) по-прежнему читается и трактуется как `kind=service` — обновлять его вручную не нужно. Альтернатива — перед строкой `/* That's all, stop editing! */` в `wp-config.php` задать `define( 'VKT_ACCESS_TOKEN', 'YOUR_ACCESS_TOKEN' );`. Константа всегда трактуется как сервисный ключ, имеет приоритет над настройками, её значение не возвращается интерфейсу. Тестовые реквизиты сообщества также находятся только в `wp-config.php`. Интерфейс и REST никогда не получают токены или Callback-секрет обратно — только безопасный статус подключения.

## Экраны

- **Обзор**: счётчики по роликам и постам, быстрый старт и лидеры по приросту просмотров в час.
- **Поиск трендов**: обход стены сообщества через `wall.get` по 100 постов, фильтр клипов и постраничный просмотр. Просмотр не записывает историю, пока пользователь не сохранит ролик.
- **Посты**: витрина постов отслеживаемых сообществ. Карточки или таблица, отдельный выбор сообщества над лентой, поиск по тексту поста, товару и сообществу, сортировка по приросту за час, сутки, 3, 7 и 30 дней, по просмотрам, ERR, вирусности, лайкам, комментариям и датам. Фильтры задают диапазоны прироста в час и за сутки, просмотров, подписчиков сообщества, вирусности, ERR и цены товара; отдельно — только посты с товаром или ссылкой, только с ценой, скрыть рекламные. Чипы периода ограничивают выдачу постами за 24 часа, 7 или 30 дней. В карточке — просмотры, прирост за час и за сутки, лайки, репосты, комментарии, ERR, вирусность, товар с ценой и артикулом, ссылки на пост VK и на товар. Кнопка «График» открывает динамику с диапазонами 24 часа, 3 дня, 7 дней, по дням и за всё время.
- **Товары в постах**: карточка показывает магазин, название товара, цену и артикул. Источники данных по убыванию точности: заголовок со страницы магазина, вложение `market` (товар сообщества), карточки карусели `pretty_cards`, заголовок карточки ссылки, название из текста поста. Если ссылок несколько, дополнительные товары доступны под «Ещё ссылок». Каждый хранит своё название, адрес и цену. Фильтры магазина, цены и распознавания проверяют один и тот же товар, включая дополнительные ссылки. Распознанным считается название из товарного вложения VK или со страницы магазина; подсказка из текста в этот счётчик не попадает.
- **Сообщества**: сводка по всем источникам — подписчики, число собранных постов, суммарные просмотры, прирост за 24 часа, 3, 7 и 30 дней, средний ERR и вирусность, дата последнего поста. Сортировка по любому из показателей, переход к постам конкретного сообщества, пауза источника.
- **Автопостинг**: синхронизация администрируемых и редактируемых сообществ, выбор нескольких адресатов, редактор текста и файлов с сервера, генерация текста/изображения/видео через xAI, немедленная или запланированная публикация, необязательная ручная проверка, очередь и результат отдельно по каждой группе.
- **Мои ролики**: до 24 карточек на страницу, фильтр по названию, сортировка, график последних 120 замеров, очередь обновления, ручные связи с товарами и удаление.
- **Товары**: название, ссылка, связанные ролики, сумма их последних просмотров и доступных скоростей прироста. Суммы не являются оценкой продаж или уникального охвата.
- **Источники**: короткое имя сообщества из адреса `vk.com` либо числовой ID владельца стены. ID сообщества — со знаком минус. Источник можно приостановить или удалить.

Плагин резолвит их пачками по 100 через `groups.getById`, сохраняет числовой ID и название сообщества, дубликаты пропускает. Кнопка «Выгрузить» отдаёт готовый список для переноса.

- **Сбор данных**: расписание, ручная порция до двух заданий, статусы, повтор ошибок. Ручная порция работает и на паузе.
- **Журнал**: последние 100 запросов, хранение 30 дней. Только метод, источник запуска, статус, код, безопасное описание и время; без параметров и сырых ответов VK.

## Товарные ссылки

Из ответа VK читаются `market` с названием, ценой, старой ценой и артикулом; `pretty_cards` как на уровне поста, так и во вложении с полем `cards`; карточки `link` с названием и `product.price`. Разбор проходит по вложенным `copy_history`, даже когда у внешнего репоста есть собственный текст, а также ищет ссылки в описаниях видео и текстах фото. Цены `market.price.amount`/`link.product.price.amount` переводятся из копеек; строковые цены карусели остаются в рублях.

Чего в ответе нет: охватов по демографии, источников переходов и статистики записи из `stats.*` — эти методы требуют прав администратора сообщества.

Всё остальное плагин достаёт со страницы магазина. Ссылка из поста сохраняется в отдельную таблицу и читается **один раз на адрес**, сколько бы постов на неё ни ссылалось. Плагин ходит сам только по доменам из списка известных магазинов (Ozon, Wildberries, Яндекс Маркет, Мегамаркет, Магнит Маркет, Lamoda, DNS, Ситилинк, М.Видео, Эльдорадо, Спортмастер, Детский мир, Золотое яблоко, Лэтуаль, аптеки, ВсеИнструменты и другие) и по сокращателям вроде `vk.cc`, у которых магазин выясняется после редиректов. Остальные адреса ждут кнопки «Прочитать» в карточке поста. Ссылки внутри `vk.com` не читаются вовсе.

Со страницы берутся название, цена и картинка: JSON-LD `Product` (массивы, `@graph`, `mainEntity`, массивы `@type`/`offers`, объект `image`), микроданные Product, товарные OpenGraph-метатеги. В JSON состояния приложения выбирается объект с ID текущего товара, чтобы не подставлять рекомендации. Метаданные внутри скриптов разбираются как JSON, включая Unicode-экранирование и разный порядок ключей; JavaScript не исполняется. Один общий `<title>` или логотип магазина не считается распознанным товаром. Запрос идёт через `wp_safe_remote_get`, который проверяет адрес и редиректы.

Если магазин ответил `403`, `429` или показал проверку на робота, ссылка получает статус «магазин закрыл доступ»: заголовок заглушки в товары не попадает, а в карточке остаются данные от VK и кнопка повтора. Автоматических попыток не больше трёх на адрес. За один прогон сборщика читается не больше двух ссылок, и это запросы к магазинам, а не к VK, — лимит API они не расходуют.

### Когда магазин закрыт

Проверено 07.09.2026 с обычного сервера: Ozon отвечает бесконечным редиректом `?__rr=` на простой запрос и `403` с JS-проверкой на полный набор браузерных заголовков с cookies; их внутренний `composer-api` и обращение с User-Agent превью-бота дают тот же результат. Ни один способ без исполнения JavaScript карточку не открывает.

Поэтому у плагина есть два ответа на такую ситуацию.

**Данные из самого поста.** Разбираются все ссылки, а название и цена ищутся рядом с каждой из них. Ссылка на другой пост VK не мешает найти следующую внешнюю ссылку. Поддерживаются подписи `[https://…|название]`, ссылки без протокола на известные магазины и обёртки `vk.com/away.php?to=…`. Длинные вступления не выдаются за название товара: при недостатке данных показывается «Название товара не определено». Предполагаемые название и цена помечаются как данные из текста; артикул извлекается из URL без запроса в магазин. Лимит — 20 отдельных адресов на пост.

**Обновление до 0.9.0.** Нужно загрузить всю папку плагина, включая новые `class-commerce.php` и `class-product-page.php`. Схема базы обновится при первом запросе. Уже сохранённые посты разбираются порциями по 100 при открытии ленты и при работе сборщика; счётчики и история замеров сохраняются. Остаток переразбора виден над лентой. Раньше необнаруженные и несохранённые вложения появятся после следующего обхода соответствующей стены VK. Старые ответы «товара в разметке нет» у известных магазинов получают одну дополнительную попытку новым парсером; заблокированные страницы автоматически повторно не запрашиваются. Это не обход антибота: HTTP 403/429 и CAPTCHA остаются блокировкой, доступные названия берутся из VK или текста.

**Сервис рендеринга.** В настройках можно указать адрес стороннего сервиса с меткой `{url}` — например `https://api.scraperapi.com/?api_key=КЛЮЧ&url={url}`. Тогда запросы к магазинам идут через него, он исполняет JavaScript и отдаёт готовый HTML, а таймаут поднимается до 45 секунд. Адрес хранится отдельной опцией и наружу не отдаётся: интерфейс видит только хост сервиса, ключ доступа остаётся на сервере. Пустое поле настройки ничего не меняет, дефис очищает сохранённый адрес.

## Метрики постов

**Прирост** — разница просмотров между текущим замером и опорным. Для окна в N дней опорным считается последний замер в интервале от `N + N/2` до `N` дней назад: слишком старая точка не годится, поэтому при паузе в сборе окно честно остаётся пустым, а не показывает завышенный прирост. Прирост в час считается по предыдущему замеру не моложе минуты. Уменьшение счётчика не превращается в отрицательный прирост — окно остаётся неизвестным.

**ERR** — сумма лайков, репостов и комментариев, делённая на просмотры, в процентах. Если ни один из счётчиков вовлечения не пришёл, ERR не считается.

**Вирусность** — просмотры, делённые на число подписчиков сообщества. Значение больше единицы означает, что пост собрал больше просмотров, чем у сообщества подписчиков. Подписчики приходят в том же `wall.get` с `extended=1&fields=members_count`.

Ни ERR, ни вирусность не являются оценкой продаж. Это отношения счётчиков, которые отдаёт VK.

## Хранение истории постов

Каждый обход источника читает 100 постов и обновляет их счётчики. Точка истории добавляется, только если счётчики изменились либо с прошлой точки прошло больше шести часов — иначе остановившийся пост копил бы одинаковые строки каждый час.

Накопленная история прореживается по возрасту: за последние 48 часов остаются все замеры, между 48 часами и 7 днями — по одному в час, старше 7 дней — по одному в сутки. Прореживание запускается не чаще раза в час вместе с очисткой журнала и работает даже на паузе сбора. Поэтому графики за 24 часа и 3 дня остаются подробными, а месячная динамика строится по дневным точкам.

Удаление источника удаляет собранные с него посты вместе с их историей: посты собираются автоматически и без источника не имеют смысла. Сохранённые ролики при этом остаются — их пользователь добавлял сам.

## Что означает тренд

`(последние просмотры − предыдущие просмотры) / время между замерами в часах`.

Для сравнения выбирается ближайший предыдущий замер не моложе одной минуты. До его появления скорость неизвестна. Отсутствующий счётчик хранится как `NULL`, а не ноль. При уменьшении счётчика скорость не рассчитывается. Значения в карточках относятся к разным фактическим интервалам: это не фиксированный прирост за сутки. Дата последнего замера видна в меню ролика. Точность зависит от частоты обновления статистики самим VK.

## Расписание на хостинге

Встроенное событие `vkt_collect` назначено раз в минуту. Оно ставит в очередь до 30 просроченных источников и до 30 роликов, обрабатывает до 2 готовых заданий. **Обход сообществ идёт первым**: пока в очереди есть источники, ролики ждут — свежие посты важнее переизмерения старого ролика.

Частота задаётся раздельно и выбирается из списка: раз в час, в 2, 3, 4, 6, 12 часов или в сутки. «Обход сообществ» отвечает за посты и видео со стены, «Замеры роликов» — за точечное обновление счётчиков сохранённых роликов. Настройка прошлых версий (один интервал в минутах) переносится в ближайшее допустимое значение автоматически. Каждый обход источника читает до 100 постов и берёт из них и все видео, и сами посты со счётчиками — дополнительных запросов к VK сбор постов не добавляет. Сохранение постов отключается флажком «Сохранять посты сообществ при обходе стены» в настройках, автоматическое чтение страниц магазинов — флажком «Читать страницы товаров по ссылкам известных магазинов». По умолчанию сообщества обходятся раз в час, ролики измеряются раз в 6 часов. Это ограниченная выборка, а не полный обход всего VK.

Для стабильной работы добавьте в cron хостинга (замените путь и бинарник PHP на реальные):

```cron
* * * * * /usr/bin/php /ABSOLUTE/PATH/TO/public_html/wp-cron.php >/dev/null 2>&1
```

После проверки системного cron можно задать `define( 'DISABLE_WP_CRON', true );` в `wp-config.php`. Сам плагин не редактирует конфигурацию и системное расписание. Исключите главную, созданные страницы и `vk-trends/v1/*` из внешнего кеша/CDN, если он подключён: приватные страницы и REST выставляют запрет кеширования на стороне WordPress.

API-запросы сериализованы общей блокировкой, после запроса выдерживается минимум одна секунда; таймаут 15 секунд, размер ответа до 2 МБ, `count` до 100. Сборщик использует отдельную блокировку на 120 секунд. Зависшее задание возвращается в очередь спустя 180 секунд. Временные ошибки повторяются до четырёх попыток с увеличением задержки. Окончательные ошибки остаются в очереди до ручного повтора; CAPTCHA автоматически не решается.

## Два режима сбора: сервисный ключ и пользовательский токен VK ID

Метод действующего токена определяет, как именно плагин ищет ролики.

**Сервисный ключ** (`VKT_API::mode() === 'service'`): весь сбор идёт через `wall.get` — до 100 постов за запрос вместе с видео-вложениями и счётчиками просмотров. Точечного замера одного ролика нет: обновление счётчиков — это переобход той же стены. `video.get`, `video.search` и `market.search` сервисному ключу недоступны (ошибка 28), `wall.getById`, `wall.search`, `utils.resolveScreenName` — ошибкой 1051.

**Пользовательский токен VK ID** (`VKT_API::mode() === 'user'`, приложение типа Web, scope с доступом к видео):
- Точечный замер уже отслеживаемого ролика идёт через `video.get(videos=owner_id_video_id)` — точнее и дешевле переобхода стены.
- Обход источника с числовым ID владельца (`kind=owner`) дополнительно читает видеораздел через `video.get(owner_id=...)` и сливает его с роликами из `wall.get` по ключу `owner_id_video_id`; при совпадении ID данные видеораздела не перезаписываются постом со стены. Источники по короткому имени (`kind=domain`) видеораздел не получают: `video.get` принимает только числовой `owner_id`, а `utils.resolveScreenName` недоступен даже пользовательскому токену (ошибка 1051).
- `video.search` **не подключается ни в одном режиме**: проверено эмпирически — он отвечает ошибкой 1051 даже с пользовательским токеном, упираясь в тип приложения, а не в права токена.

Тип ролика берётся из ответа VK: `short_video` у клипа, `video` у обычного ролика — это точнее прежнего фильтра `filters=short`.

Проверено на живом API: сервисным ключом — `wall.get` и `groups.getById` работают, `wall.getById`/`wall.search`/`utils.resolveScreenName` отвечают ошибкой 1051, `video.*` — ошибкой 28. Пользовательским токеном VK ID — `video.get` (точечно и по `owner_id`), `wall.get`, `users.get` работают; `video.search` и `newsfeed.search` отвечают ошибкой 1051.

## Автообновление пользовательского токена

Перед каждым запросом к `api.vk.com` плагин проверяет срок пользовательского токена. Если сохранены `expires_at` и полный комплект `refresh_token` + `device_id` + `client_id`, то меньше чем за 5 минут до истечения он обновляет пару запросом `POST https://id.vk.ru/oauth2/auth` с `grant_type=refresh_token`. Обновление защищено отдельной блокировкой (`VKT_Store::lock('token_refresh', 20)`) — параллельные запросы не обновляют токен повторно. Если `id.vk.ru` недоступен или отклонил обновление, запрос к VK не выполняется и возвращается понятная ошибка на русском. Итог обновления виден в «Журнале» как `oauth2.auth`. Пользовательский токен без refresh-комплекта не обновляется автоматически; если для него указано время жизни, после истечения нужно сохранить новый. Сервисный ключ не имеет срока действия и никогда не обновляется автоматически.

## Границы версии

Посты собираются только со стен источников и только последние 100 за обход: пост, ушедший за сотый, новых замеров не получит, а история по нему сохранится. Точечного замера отдельного поста нет ни в одном режиме — `wall.getById` отвечает ошибкой 1051 и сервисному ключу, и пользовательскому токену, поэтому счётчики постов обновляются исключительно переобходом стены. Товары извлекаются из вложений, репостов и ссылок. Ссылки на VK Market сохраняются как товарные; ссылки на другие посты `wall…` не считаются товарами и не обходятся рекурсивно. Если магазин блокирует запросы и VK не отдал название, точно определить его по одному URL нельзя. Охваты по демографии, источники переходов и статистика записи через `stats.*` недоступны — они требуют прав администратора сообщества.

С сервисным ключом в выдачу попадают только ролики, опубликованные постом на стене; клип, выложенный мимо стены, собран не будет, а точечного замера нет — счётчики обновляются переобходом стены, поэтому ролик, ушедший за сотый пост, новых замеров не получит. С пользовательским токеном VK ID точечный замер и видеораздел owner-источников снимают оба этих ограничения, но только для источников с числовым ID; короткое имя (`domain`) по-прежнему ограничено `wall.get`. Глобального поиска видео по всему VK нет в обоих режимах — работа строится от списка источников, `video.search` не подключён. Счётчики лайков и репостов во вложении `wall.get` не приходят и остаются `NULL`. Отдельный API ленты Шопсов и автоматическое извлечение товарных привязок не реализованы. Связи товаров с роликами задаёт пользователь. Закрытые ролики с `access_key` не поддерживаются.

Каталог тестов включает `wall.get`, `video.get`, `video.search`, `video.getComments`, `video.getAlbums`, `market.get`, `market.search`, `market.getById`, `market.getCategories`, `users.get`, `groups.getById`, `groups.search`, `wall.get`, `wall.search`, `wall.getById`, `utils.resolveScreenName`, `likes.getList`. Справка параметров взята из официальной схемы VK 5.199.99, проверена 06.09.2026. Настройка версии HTTP API по умолчанию — 5.199. Все методы VK и внутренние методы мобильного приложения не включены.

До 500 источников и 500 товаров. Витрина постов отдаёт 24 карточки на страницу, сводка сообществ — до 500 строк. История замеров сохраняется без автоматического удаления; оцените объём базы при длительном сборе. Удаление ролика удаляет его замеры и связи. Удаление источника сохраняет собранные ролики. Деактивация останавливает расписание и возвращает тему, данные и созданные страницы сохраняются. Удаление плагина через WordPress также не стирает накопленные данные автоматически.

## Локальная проверка

`php -l` для PHP и `node --check assets/dashboard.js` для JS. `php tests/commerce.php` проверяет извлечение и реальные SQL-фильтры на временной SQLite-базе в памяти; `node tests/dashboard-commerce.cjs` проверяет HTML-шаблоны и обработчики фильтра без браузера; `php tests/publisher.php` проверяет схему автопостинга и строгий формат вложений; `php tests/community.php` проверяет, что статус сообщества не раскрывает ключ и Callback-секрет; `php tests/media.php` проверяет отбор файлов медиатеки и разбор ответов xAI на записанных форматах живого API, включая то, что ключ не уходит наружу; `php tests/settings-token.php` проверяет разбор вставленного адреса с токеном; `php tests/tokens.php` проверяет изоляцию слотов, шифрование и перенос ключа старого формата; `php tests/token-preview.php` проверяет, что огрызок токена опознаёт сохранённое, но не раскрывает его; `php tests/vkid.php` проверяет PKCE-подключение VK ID: соответствие `code_challenge` сохранённому verifier, отказ при заданной константе `VKT_ACCESS_TOKEN` и подмену чужого адреса возврата своим. Эти сценарии работают без сети и не обращаются к рабочей базе. Интеграционный сценарий `tests/integration.php` запускается только в отдельном тестовом WordPress через `wp eval-file`; он создаёт и очищает тестовые данные, перехватывая HTTP как к `api.vk.com`, так и к `id.vk.ru` (включая `groups.get`, `wall.post`, загрузку фотографии через `photos.getWallUploadServer`/`photos.saveWallPhoto` и обновление пользовательского токена). **Не запускать на рабочей базе**. Проверки с подменёнными ответами не подтверждают доступность методов с реальным токеном.
