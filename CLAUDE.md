# VK Trends — контекст проекта

Плагин WordPress `vk.fastfixsite.ru/public_html/wp-content/plugins/vk-trends`: дашборд трендов VK с личными кабинетами, автопостингом и стендом генерации изображений. Остальные файлы репозитория (`find_vk_groups.py` и прочее) к плагину отношения не имеют.

## Правила работы

- **Правки — сразу в папке плагина.** Без копий в scratchpad и без ожидания «ок» (пользователь 28.09.2026: «всегда пиши сразу в файл плагина!»). После правок — прогнать тесты и перечислить изменённое.
- **Архив не собирать.** Пользователь заливает папку плагина сам, `.zip` ему мешает.
- **Заливает и коммитит только пользователь.** Харнесс режет FTP и передачу учётных данных; проверять результат снаружи — сравнением первой строки `README.md` и md5 `assets/dashboard.js`.
- **Комментарии и интерфейс на русском.** Комментарий объясняет причину, а не пересказывает код.
- После правок — список изменённых файлов, отдельно новые: их легко пропустить при выборочной заливке.

## Тесты

```
php tests/<имя>.php            # офлайн, без сети и WordPress
node tests/dashboard-commerce.cjs
```

Интеграционные (`tests/accounts-integration.php`) идут только в изолированной установке WordPress на `http://127.0.0.1:8097` — поднимается в scratchpad (ядро + wp-cli), база `vkt_test` в локальном MySQL. Прежний `tests/integration.php` устарел с 0.19.2 и падает ещё до правок.

## Устройство

Кабинеты: роль `vkt_member`, вход через VK ID, доступ после одобрения. Общее для сайта — сервисный ключ, приложение VK, ключи BFL и Wiro, расписание сбора, журнал. Личное — пользовательский токен, ключ сообщества, группы, очередь публикаций, источники, ролики, товары. Константы из `wp-config.php` действуют только для хозяина сайта (`vkt_owner`). У cron нет пользователя, поэтому очередь публикаций выполняет каждое задание через `VKT_Account::act_as( автор )`, а сборщик — от имени хозяина.

Источники общие: сообщество обходится один раз, видимость даёт подписка (`vkt_subscriptions`), ролики — список `vkt_user_videos`.

Стенд генерации — `VKT_Flux` (api.bfl.ai); класса для fal.ai в плагине нет и не было. Картинки к записям рисует реестр `VKT_Images` (xAI, OpenAI, Wiro, BFL), модель выбирается значением вида `bfl:flux-2-pro` / `wiro:z-image-pro`. Следующий шаг — третий поставщик «Свой сервер»: ComfyUI с Qwen-Image-Edit на арендованном GPU.

## Агенты — замысел (обсуждено 26.10.2026, ничего не реализовано)

Сейчас нейросеть в плагине вызывается одним запросом (`VKT_AI::rewrite_article`, `news_headlines`, серии, `VKT_Images`): что делать с результатом, решает код. Агентом считается петля, в которой модель смотрит на свой результат и выбирает следующий шаг. Нужны две разные петли:

- **Петля 1 — внутри работы, на каждый пост.** Новости: сверка с `news.recent`, проверка факта по второму источнику, отсев кликбейта. Текст: черновик → сверка с паспортом и «Визуалом» (тон, длина, запреты) → правка → проверка форматирования VK. Картинка: нарисовал → оценил vision-моделью (похож ли персонаж, цел ли текст обложки, нет ли артефактов) → перерисовал; при отказе модерации BFL сам переформулирует или уходит на gpt-image. Ответы на комментарии: учёт ветки и базы ведения, провокации — пользователю. **Публикация (`wall.post`) остаётся кодом**: известные ошибки (истёк токен, 1051, частота) обрабатывает код, агента зовут только на незнакомую ошибку.
- **Петля 2 — поверх работы, цикл за циклом.** Раз в неделю агент разбирает `stats.get` (длина, время, стиль картинки, рубрика → охват и реакции) и **предлагает** поправки: сетка серии, длина по умолчанию, дополнения к паспорту. Применяет пользователь.

Границы:
- Во время работы агент меняет только **данные** в базе (промпты, настройки группы, сетка серии, черновики) и никогда не правит код плагина на бою.
- Решения пользователя — паспорт, запреты, лимиты `ai_spend`, режим «публиковать без подтверждения или нет» — агент читает, но не меняет; поправки к ним только предлагает.
- Код чинит отдельная самовосстанавливающаяся петля только на маке пользователя: сбой → Claude Code правит код → `php tests/*.php` → коммит → заливает пользователь. Проверки «что должно получиться» агент не трогает; если для починки нужно менять проверку, решение за пользователем.
- Лимит попыток на каждую петлю; после него — стоп и оповещение через `VKT_Notify`.

Железо: Beget ограничивает время PHP-запроса, длинную петлю в одном заходе cron не прогнать. Петля 1 — пошаговый агент в плагине: один шаг за заход cron, состояние в базе, как автосбор с `news_auto_at`. Петля 2 и починка кода — на маке через `tg-agent` (`~/kostyan13/lk/tg-agent`, уже умеет запускать Claude Code) + Claude Code.

Пилот — картинки «нарисовал → проверил → перерисовал» поверх `VKT_Images`: самая болезненная часть (модерация BFL, персонаж, текст обложки), результат виден глазами, петля короткая. Потом тот же подход перенести на текст и новости.
